# Digital Canvas for iPhone and Android

`apps/mobile` wraps the web editor (`apps/web`) in [Capacitor](https://capacitorjs.com) 8 (MIT) native shells:

- App id / bundle id: **`com.panth977.digitalcanvas`**, name **Digital Canvas**
- `capacitor.config.ts`: `webDir` = `../web/dist` (the built web app is copied into each app)
- `ios/` (Xcode project, Swift Package Manager, no CocoaPods) and `android/` (Gradle) are generated by `cap add` and committed; build outputs are git-ignored
- Plugins: `@capacitor/app` (app links), `@capacitor/browser` (Google sign-in in the system browser), `@capacitor/share` + `@capacitor/filesystem` (exports go to the share sheet), `@capacitor/camera` (photo library picker), `@capacitor/splash-screen`; core `SystemBars` makes the WebView edge to edge so CSS `env(safe-area-inset-*)` works
- The web code only loads these plugins through dynamic `import()` behind `isNative()` (`apps/web/src/lib/native/`), so browsers download nothing extra.

## Build

From the repo root:

```sh
npm install
npm run build                          # apps/web → apps/web/dist
cd apps/mobile && npx cap sync         # copy dist + plugins into ios/ and android/
```

Run `npx cap sync` again after every web build (or `npm run sync -w @digital-canvas/mobile`, which does both).

Icons and splash screens are rendered from `apps/web/public/favicon.svg`'s design by `node apps/mobile/scripts/icons.mjs` (uses Playwright's Chromium). It also writes the PWA icons in `apps/web/public/icons/`.

## iOS

Needs Xcode (tested with Xcode 27.1, iOS 18.1 simulator; the app targets iOS 15+).

Simulator, from the command line:

```sh
cd apps/mobile/ios/App
xcodebuild -project App.xcodeproj -scheme App -configuration Debug \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /tmp/dc-ios CODE_SIGNING_ALLOWED=NO build
xcrun simctl list devices available             # pick an iPhone (or: xcrun simctl create "DC iPhone" com.apple.CoreSimulator.SimDeviceType.iPhone-16-Pro com.apple.CoreSimulator.SimRuntime.iOS-18-1)
xcrun simctl boot <UDID>
xcrun simctl install <UDID> /tmp/dc-ios/Build/Products/Debug-iphonesimulator/App.app
xcrun simctl launch <UDID> com.panth977.digitalcanvas
xcrun simctl io <UDID> screenshot shot.png
xcrun simctl shutdown <UDID>
```

Or `npx cap open ios` and press Run in Xcode.

### On your own iPhone

1. Open `apps/mobile/ios/App/App.xcodeproj` in Xcode (`npx cap open ios`).
2. Xcode → Settings → Accounts → add your **Apple ID**.
3. Select the **App** target → *Signing & Capabilities* → tick *Automatically manage signing* → choose your **Team**. Keep the bundle id `com.panth977.digitalcanvas` (if Xcode says it is taken for a free account, use e.g. `com.panth977.digitalcanvas.dev`; the URL scheme in Info.plist stays `com.panth977.digitalcanvas`, so sign-in still works).
4. Plug in the iPhone (or pair it over Wi-Fi), turn on *Developer Mode* (Settings → Privacy & Security → Developer Mode), pick it as the run destination and press Run. The first time, trust the developer certificate on the phone: Settings → General → VPN & Device Management.

What each Apple account allows:

| | Free Apple ID (Personal Team) | Apple Developer Program (99 USD/year) |
|---|---|---|
| Install from Xcode on your own devices | yes, up to 3 devices | yes, up to 100 devices per type |
| How long an install keeps working | **7 days**, then re-run from Xcode | 1 year (development profile) |
| TestFlight (install over the air, up to 10,000 testers) | no | yes |
| App Store | no | yes |

For TestFlight: join the program, create the app in App Store Connect with bundle id `com.panth977.digitalcanvas`, then in Xcode *Product → Archive → Distribute App → App Store Connect → Upload*, and add testers in App Store Connect → TestFlight.

## Android

Capacitor 8's Android Gradle plugin needs **JDK 21**. The JDKs in `/Library/Java` are 11 and 17, so use the one inside Android Studio:

```sh
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
cd apps/mobile/android
./gradlew assembleDebug        # → app/build/outputs/apk/debug/app-debug.apk
```

(`local.properties` with `sdk.dir` is written by `cap add`/Android Studio and is git-ignored; set `ANDROID_HOME=~/Library/Android/sdk` if Gradle can't find the SDK.)

Emulator (an AOSP image is enough; Google sign-in needs a browser, which the Play/Google APIs images have):

```sh
sdkmanager "emulator" "system-images;android-35;default;arm64-v8a"      # ~0.42 GB + ~0.77 GB
avdmanager create avd -n dc_api35 -k "system-images;android-35;default;arm64-v8a" -d pixel_7
emulator -avd dc_api35 -no-window -no-audio -no-boot-anim -gpu swiftshader_indirect &
adb wait-for-device
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.panth977.digitalcanvas/.MainActivity
adb exec-out screencap -p > shot.png
adb emu kill
```

### On your own Android phone

Debug build: phone → Settings → About phone → tap *Build number* 7 times → Developer options → *USB debugging* on. Connect it, accept the prompt, then `adb install -r app/build/outputs/apk/debug/app-debug.apk`. (Or copy the APK to the phone and open it, allowing "install unknown apps".)

Release build (for sharing or the Play Store):

```sh
keytool -genkeypair -v -keystore ~/digital-canvas-release.jks -alias digitalcanvas \
  -keyalg RSA -keysize 4096 -validity 10000       # keep this file and its passwords safe, never commit them
```

Add to `~/.gradle/gradle.properties` (not the repo):

```
DC_RELEASE_STORE_FILE=/Users/<you>/digital-canvas-release.jks
DC_RELEASE_STORE_PASSWORD=…
DC_RELEASE_KEY_ALIAS=digitalcanvas
DC_RELEASE_KEY_PASSWORD=…
```

and a `signingConfigs.release` in `android/app/build.gradle` that reads them, then `./gradlew assembleRelease` (APK) or `./gradlew bundleRelease` (AAB for Play). Play Console needs a one-time 25 USD developer account.

## Google sign-in in the app

Google blocks OAuth inside embedded WebViews, so the app signs in through the **system browser** (SFSafariViewController on iOS, a Chrome Custom Tab on Android), reusing the **web** OAuth client and the backend unchanged:

1. `account.signIn()` / `connectWholeDrive()` / the Drive re-consent path call `getCode()` (`apps/web/src/lib/google.ts`). On native that is `nativeRequestCode()` (`lib/native/oauth.ts`): it opens
   `https://accounts.google.com/o/oauth2/v2/auth?client_id=<web client>&redirect_uri=https://digital-canvas-p977.web.app/auth/callback&response_type=code&access_type=offline&include_granted_scopes=true&prompt=select_account|consent&scope=…&state=dcapp.<uuid>`.
2. Google redirects the browser to the **hosted** web app's `/auth/callback`. There, `lib/native/bounce.ts` (the first module `main.ts` runs) sees the `dcapp.` state and immediately sends the browser to `com.panth977.digitalcanvas://auth?code=…&state=…`, with a visible **Return to Digital Canvas** button as a fallback. The web app itself does not boot on that page.
3. The app gets the URL through `@capacitor/app`'s `appUrlOpen` (iOS `CFBundleURLTypes`, Android `VIEW` intent-filter on a `singleTask` activity), checks the state, closes the browser and calls the backend's `googleSignIn({ code, redirectUri: 'https://digital-canvas-p977.web.app/auth/callback' })`, which the backend already accepts. The rest (custom token, Drive token) is the same as on the web.

**CORS:** the WebView's origin is `capacitor://localhost` (iOS) / `https://localhost` (Android), which is not in the functions' CORS list. Without touching the backend, the app sends only Cloud Functions requests (`*.cloudfunctions.net`, `*.run.app`) through native HTTP (`CapacitorHttp`) via a targeted `fetch` wrapper (`lib/native/http.ts`); global CapacitorHttp patching stays off, so Drive uploads keep the WebView's fetch (googleapis.com allows any origin).
Alternative (one line, owner's call): add the two origins to `ORIGINS` in `backend/functions/src/index.ts`:
`const ORIGINS = ['http://localhost:5181', 'https://digital-canvas-p977.web.app', 'https://digital-canvas-p977.firebaseapp.com', 'capacitor://localhost', 'https://localhost'];`
— careful: `googleSignIn` also uses `ORIGINS` to accept `<origin>/auth/callback` redirect URIs, so keep that check on the first three only if you do this.

Firebase Auth in a WebView: `apps/web/src/lib/icebase.ts` initialises Auth with IndexedDB persistence and no popup resolver on native (the default `getAuth()` never reports a user in a WebView).

### What the owner has to do

1. **Deploy the web app** (`npm run deploy:web`) once this branch is merged. The bounce code runs on the hosted `/auth/callback`; until it is deployed, sign-in in the app ends on the web app's callback page instead of returning to the app.
2. Nothing in Google Cloud is needed for this design: `https://digital-canvas-p977.web.app/auth/callback` is already an authorised redirect URI of the web client (the web redirect flow uses it). Check it is listed under Google Auth Platform → Clients → the web client → *Authorised redirect URIs*.
3. While the OAuth app is in **testing** mode, only listed test users can sign in (same as the web).

### Optional: native Google Sign-In clients

Only needed if you later switch to the native Google Sign-In SDKs instead of the browser flow. These can't be created with `gcloud` (`gcloud iam oauth-clients` is for Workforce Identity Federation, not Google sign-in clients), so use the console: <https://console.cloud.google.com/auth/clients?project=digital-canvas-p977> → **Create client**:

- **iOS**: Application type *iOS*, bundle ID `com.panth977.digitalcanvas` (App Store ID / Team ID optional). Google gives a client id and a reversed-client-id URL scheme to add to Info.plist.
- **Android**: Application type *Android*, package name `com.panth977.digitalcanvas`, SHA-1 of the signing certificate. One client per certificate:
  - debug keystore on this Mac (`keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android`): `18:C2:5E:E1:B6:9D:B5:AC:7D:55:A4:A2:AF:59:89:6B:3A:9F:78:B7`
  - release: the SHA-1 of your release keystore (`keytool -list -v -keystore ~/digital-canvas-release.jks -alias digitalcanvas`), and if you use Play App Signing, also the *App signing key* SHA-1 from Play Console → Setup → App integrity.

Native clients have no secret, so the backend would need to exchange their codes (or verify their ID tokens) differently; that is a backend change.

## Other native behaviour

- **Exports** (`download()` in `lib/files.ts`): written to the app's cache folder and handed to the share sheet (Save to Files / Save Image / AirDrop / other apps). Several pages are shared together instead of zipped.
- **Photos**: Uploads has a *Photos and videos* button (system photo picker, several at once); image-only pickers elsewhere also open the photo library. Picked items become `File`s, so the normal upload path (Drive `Digital Canvas/assets`) is unchanged. Usage strings: `NSPhotoLibraryUsageDescription`, `NSCameraUsageDescription`, `NSPhotoLibraryAddUsageDescription`; Android uses the system Photo Picker (`READ_EXTERNAL_STORAGE` only up to API 32).
- **App links**: `com.panth977.digitalcanvas://new[?w=&h=&title=]` makes a design and opens it; `com.panth977.digitalcanvas://open/d/<id>` opens one. iOS asks before opening a link from outside, so for scripted simulator runs the start page also accepts `?applink=new` (via Capacitor `server.appStartPath`).
- The PWA service worker is **not** used inside the app (the files are already on the device), so offline Drive caching is a browser/PWA feature only.

## AI on this device (device bridge)

"Let AI use this device" (File › Settings › AI and devices) makes the app run the AI connector's tool calls (see packages/mcp/README.md, Device bridge).

- **Android:** while it is on, the local plugin `BridgeKeepAlive` (`android/app/src/main/java/com/panth977/digitalcanvas/BridgeKeepAlivePlugin.java`) starts `BridgeKeepAliveService`, a foreground service of type `specialUse` with a quiet ongoing notification and a partial wake lock, so the app keeps answering in the background. It asks for the notification permission on Android 13+ (the service runs either way). Turning the switch off stops it. Play Store review needs the `specialUse` justification (in the manifest's `PROPERTY_SPECIAL_USE_FGS_SUBTYPE`).
- **iOS:** there is no equivalent background mode for this; the app works for the AI only while it is open on screen. The panel says so.
